# CLAUDE.md — правила работы над СКАТ 2.0 (читать первым)

## Пользователь
- Пишет по-русски. Только iPhone/iPad, компьютера нет. Claude Pro — **экономить лимит**.
- Ответы краткие, по делу.
- Перед каждой доработкой: план + оценка расхода (% 5-часового окна) → ждать «Да / Делай / Продолжай». Мелкие исправления до ~3 % — сразу.
- В конце **каждого** ответа:
  - «Версия: X»;
  - «Файлы: …»;
  - ссылки: стабильная `https://984s2pbyn4-create.github.io/skat2/`, бета `…/skat2/beta/`, релизы `https://github.com/984s2pbyn4-create/skat2/releases`.
- Код правит только один чат одновременно.
- Ветки: код — в `dev`; `main` — стабильная версия и приём архивов. Workflow-файлы живут в `main`, их создаёт пользователь вручную.

## Начало чата
1. Получить код: `git clone --depth 1 -b dev https://github.com/984s2pbyn4-create/skat2` (репозиторий публичный).
2. Прочитать документы:
   - этот файл;
   - в `docs/ARCHITECTURE.md` — только нужные разделы;
   - в `docs/FEATURES.md` — строки нужных ID;
   - `README.md` затрагиваемых функций.
3. **Не читать** репозиторий целиком. Искать через `grep -rn`, выводить коротко.

## Как вносить изменения
1. Найти функцию по ID в `FEATURES.md`. Код — в `src/modes/<режим>/features/<имя>/` (ядро — в `src/kit` или `src/core`).
2. Новая функция:
   - папка по шаблону (`index.ts` манифест, `model.ts`, `logic/`, `ui/`, `map/`, `README.md`);
   - строка в `features.config.ts` режима.
3. Перед выдачей прогнать проверки в песочнице:
   - `npm ci` (один раз за чат);
   - `npm run check` — типы, линтер, границы модулей, тесты;
   - `npm run build`.

   Красное не выдавать.
4. Поднять версию в `package.json` (SemVer 2.x.y; пререлизы `-alpha.N` / `-beta.N`) и дописать `CHANGELOG.md`.
5. Обновить статус в `FEATURES.md` и `README.md` функции.
6. Собрать архив `skat2-<версия>.zip`:
   - только изменённые и новые файлы, с путями от корня;
   - удаления — списком в `_delete.txt`;
   - сообщение коммита — в `_commit.txt` (Conventional Commits).

   Положить в `/mnt/user-data/outputs/` → `present_files`.
7. Пользователь загружает архив в корень ветки `main` (Add file → Upload files → Commit) → Action `apply-patch` проверяет и коммитит в `dev` → бета обновляется. Красный крестик в Actions — архив не применён, нужен лог.
8. Выпуск стабильной версии: пользователь нажимает «Run workflow» у `release.yml`.

## Правила кода
- **TypeScript strict**, без `any` (кроме оправданных и помеченных).
- **Без глобальных переменных.** Режимы не импортируют друг друга; обмен — только через `kit/exchange` (`LayerPacket`).
- **Зависимости уровней:** core ← platform ← kit ← modes ← app (см. ARCHITECTURE §3). Нарушение = красная сборка.
- **Данные:**
  - любое изменение — командой (история ↶/↷);
  - у среза — схема zod и `version` с миграцией;
  - координаты хранятся в WGS-84 `[lng, lat]`; Оператор — в метрах СК-42 зоны проекта.
- **Логика** — чистые функции с тестами рядом (`*.test.ts`). UI — Preact + signals, тяжёлые окна грузятся лениво.
- **Язык:**
  - имена в коде — английские;
  - комментарии, тексты интерфейса и README — русские.
- **Коммиты:** `feat(BK-13): …`, `fix(OP-08): …`, `docs: …`, `chore: …`.
- **Workflow-файлы** (`.github/workflows/`) Action менять не может → выдавать отдельным файлом с инструкцией «Create new file». Исключение — если настроен секрет `WORKFLOW_TOKEN`.
- **Секреты и токены** в чат не просить и в код не класть.
